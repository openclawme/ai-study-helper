# 我的AI学习助手

> 初三 7 科智能 AI 错题本。手机拍照 → AI 识别考点、擦掉手写与红笔、生成同考点变式题 →
> 电脑端对照复习 → 一键导出 A4 打印重做。

## 快速开始

```bash
pip3 install --user --break-system-packages -r requirements.txt   # 首次
export DEEPSEEK_API_KEY=sk-你的key                                # 首次（见下）
python3 main.py
```

启动后终端会打印**访问口令**和地址：

```
  ── 访问认证（已启用）─────────────────────────────
  访问口令 ：  <启动时随机生成，也写在 password.txt 里>
  口令文件 ：  /home/admin/gcl/password.txt
```

浏览器打开 `http://<服务器IP>:8000` → 输入口令 → 进入。

## 访问认证

应用**默认开启口令登录**，所有路径都受保护 —— 包括 `/static` 下的错题照片
（只保护 API 是不够的：照片 URL 一旦泄露就等于数据泄露）。

| 机制 | 说明 |
|---|---|
| 口令来源 | 环境变量 `APP_PASSWORD` > `./password.txt` > 首次启动自动生成（12 位，已剔除 0/o/1/l 等易混字符） |
| 口令存储 | 只存 PBKDF2-SHA256 哈希（12 万轮，单次校验约 80ms） |
| 会话 | HMAC-SHA256 签名 Cookie，HttpOnly + SameSite=Lax，默认 14 天免登录 |
| 防爆破 | 单 IP 10 分钟内失败 8 次即锁定（锁定期间正确口令也拒绝） |
| 换口令 | 改 `password.txt` 后重启，或 `export APP_PASSWORD=新口令` |

**已知局限**：当前跑在明文 HTTP 上，口令在传输途中未加密。这挡得住扫描器、爬虫、
陌生人（主要威胁），但挡不住同一网络路径上的被动嗅探。要彻底解决需要 HTTPS。

### 升级到 HTTPS（强烈建议）

有域名的话用 Caddy 最省事，自动申请 Let's Encrypt 证书：

```bash
sudo apt install -y caddy
sudo tee /etc/caddy/Caddyfile >/dev/null <<'EOF'
cuoti.example.com {
    reverse_proxy 127.0.0.1:8000
}
EOF
sudo systemctl restart caddy
```

然后把 `main.py` 里 `set_cookie(...)` 的 `secure=True` 打开，并让 uvicorn 只监听
`127.0.0.1`（`uvicorn.run(app, host="127.0.0.1", port=8000)`），只让 Caddy 对外。

## 开放公网访问（阿里云）

1. 阿里云控制台 → ECS → 实例 → **安全组** → 配置规则 → 入方向 → 手动添加：
   - 协议类型 `TCP`，端口范围 `8000/8000`，授权对象 `0.0.0.0/0`
   - （更安全的做法：授权对象填你自己的 IP，如 `1.2.3.4/32`）
2. 系统防火墙本机默认是关的（ufw inactive / iptables ACCEPT），无需额外操作。
   若你后来开了 ufw：`sudo ufw allow 8000`
3. 手机浏览器访问 `http://<你的服务器公网IP>:8000`

> 开放前请确认口令登录已开启（看启动横幅有没有「访问认证（已启用）」那一段）。

## 上传按钮为什么是两个（手机相机入口的坑）

手机浏览器有一条硬规则：**`accept` 里只要出现相机拍不出来的类型，系统就不再提供
「拍照」入口**，直接跳文件浏览器。

我加文档上传支持时，把 `accept` 从 `image/*` 扩成了
`image/*,.pdf,.doc,.docx,.txt,.md` —— 结果**拍照选项当场消失**，
而拍照恰恰是这个应用最主要的用法（孩子拍作业）。这个问题在电脑上完全看不出来，
只有真机才复现。

所以拆成两个 input：

| 按钮 | accept | 作用 |
|---|---|---|
| 拍照（`md:hidden`） | `image/*` | 只收图片 → 系统才会把「拍照」摆进选项 |
| 选文件 | `image/*,.pdf,.doc,.docx,.txt,.md` | 文档走这条 |

另外**不要写 `capture="environment"`**：写了在 iOS 上会直接进相机，
反而少了「从相册选」；不写则由系统弹「拍照 / 相册 / 浏览」三选一。

顺带一提：`meta viewport` 里的 `user-scalable=no` 只影响页面缩放，
和这里的选择器行为无关 —— 别把两件事混起来查。

## 文件上传：PDF / Word / 文本

除了拍照，还能直接传**一份文件**。四种来源在代码里**先归一到「页」**，再走同一条路：

| 上传的东西 | 怎么变成「页」 |
|---|---|
| 图片 jpg/png | 1 页，就是它自己 |
| PDF | N 页，逐页用 `pypdfium2` 渲染成图（长边 1600px） |
| Word doc/docx | **先用 LibreOffice 转成 PDF**，再按 PDF 渲染 |
| 文本 txt/md | 1 页纯文字（自动认 GB18030 —— 老师发的 txt 常常不是 UTF-8） |

Word 之所以要绕 LibreOffice 而不是直接抽文字：**几何题的图、表格、公式排版抽不出来**，
只抽文字等于把题弄残。装法：

```bash
sudo apt-get install -y --no-install-recommends libreoffice-writer libreoffice-core fonts-noto-cjk
```

`fonts-noto-cjk` 不能省 —— 没有中文字体时 LibreOffice 转出来的 PDF 里中文全是方块，
而且**不报任何错**。（转换用独立的 `-env:UserInstallation` 配置目录：共用一份配置时
并发转换会互相抢锁，报的是「source file could not be loaded」这种和真实原因无关的错。）

### 拆题：一页拆成一道一道

上传后按页调用 AI，一次返回这一页上的**所有题目**，每道题各自入库成一条记录，
有自己的考点、分析、对话、打印。规则 1~4 与单张照片**共用同一份 `_EXTRACT_RULES`**
—— 复制两份的话，以后调了一边的口径另一边不会跟着变。

拆题提示词里几条关键约束：一道大题连同 (1)(2)(3) 小问算**一道**；章节标题归给下面第一道题；
**跳过答案页/解析页/答题卡/封面**；一页最多 12 道。

### 走 SSE 而不是普通 POST

一份 10 页的卷子要调 10 次 AI，可能几分钟。普通 POST 只能干等，用户看到的是转圈；
SSE 能把「正在分析第 3/10 页…已入库 7 道」实时推出来。**每页串行**：并行发十几个请求
容易被限流，失败时也不好定位是哪一页。

图片上传**保持不变**（XHR + 上传进度条）：手机拍照时上传进度更重要，
而 XHR 拿不到流式响应，两者只能选一个。

### 自动裁题：默认关闭（`DOC_AUTO_CROP`）

一页上有多道题时，本来想把每道题按 AI 给的范围从整页里裁出来。**实测做不到，默认关掉。**

试过画一把带百分数刻度的尺子在页面左边（把"估一个抽象比例"变成"读出图上的数字"），
尺子是清晰的，但模型**在一页里同时做「拆题」和「定位」两件事时，会把整页均分成 N 份**，
而不是逐题去读刻度。用尺子图当基准逐题核对：

```
题1 模型 10%~25% / 真实 14.1%~16.6%   ✅
题2 模型 25%~31% / 真实 20.4%~24.6%   ❌ 完全没沾到
题3 模型 31%~38% / 真实 30.1%~31.2%   ⚠️
题4 模型 38%~44% / 真实 33.4%~34.4%   ❌ 完全没沾到
题5 模型 44%~50% / 真实 38.4%~46.6%   ⚠️
题6 模型 50%~60% / 真实 44.0%~46.6%   ❌ 完全没沾到
```

6 道只有 1 道完全正确，而且**区间格式合法**——代码没法判断它对不对，只能照裁。
裁错的后果是「点开第 4 题，看到的是第 2 题的图」，比不裁糟得多。
所以默认**不裁**：一页上的每道题共用这张整页图，永远正确、也永远可解释。

想自己试（换一份真实试卷可能表现不同）：`DOC_AUTO_CROP=1 ./start.sh`。
打开后会自动给页面加刻度尺并在提示词里加上第 5 条「定位」。

### 来源标记

`source` 列记录这道题是从哪来的：「照片」/「《期中卷》第 3 页」/「《t》」。
**没有这列就说不清为什么三道题的「原图」长得一模一样**（它们来自同一页）。
加这列时会把老数据回填成「照片」—— 加列之前只能上传照片，这是事实不是猜测。

纯文本/来源文件没有原图时，详情页显示「无原图 / 无图」，AI 对话的提示语也会
换成「AI 手上只有题干文字」——不能让界面承诺一个不存在的东西。

## 双轨制：两个"版本B"

DeepSeek 的 `deepseek-flash` 是「文本+图片 → 文本」模型，**不能输出图片**，
所以"让 AI 擦掉红笔再吐回一张图"做不到。本项目用两条腿走：

| 版本 | 内容 | 谁做的 | 用途 |
|---|---|---|---|
| 版本A | `static/origin/original_[id].jpg` | 原图（EXIF 校正+压缩） | 看错因、查卡点 |
| 版本B-图片 | `static/clean/clean_[id].jpg` | 本机 OpenCV | 打印重做的干净底图 |
| 版本B-文字 | `clean_text` 字段 | deepseek-flash 视觉识别 | 最干净的考前重做版 |

**版本B-图片的处理链**（`make_clean_image`，参数是实测调出来的）：

1. HSV 双区间掩膜抠红笔（红色跨 0 度环绕，必须分 `[0,15]` 和 `[156,180]` 两段）
2. 掩膜膨胀后用 **`cv2.inpaint` 修复**红笔区域
3. 转灰度（**不做中值滤波**）
4. **自适应阈值**（高斯加权，块 51，C=12）

每一步都是拿真实中文卷子对比实测选出来的，几个反直觉的坑：

| 做法 | 结果 |
|---|---|
| 红笔处 `img[mask]=255` 直接置白 | 留下硬边台阶，阈值沿台阶描出**一圈黑疤** |
| 掩膜**羽化**后再 alpha 混合 | 过渡带是中间灰，被阈值判成黑，**黑疤更粗** |
| **`cv2.inpaint(TELEA)`** ✅ | 用周围纸面插值填补，无台阶无灰带，红框彻底消失 |
| 灰度后 `medianBlur(3)` 去噪 | 把中文 1~2px 细笔画**直接抹断**（"已知二次函数"断笔） |
| 自适应阈值 C=15 | 纸面干净但细笔画被削断 |
| 自适应阈值 C=8 | 笔画完整但纸面全是颗粒黑点 |
| 自适应阈值 **C=12** ✅ | 平衡点 |

> 为什么不用"背景归一化"(divide)？它需要手工指定黑白场，换张暗照片就失效；
> 自适应阈值基于局部对比，对光照梯度天然免疫。

**重要局限**：黑笔手写无法用像素方法剥离（它和印刷体都是黑色，任何"去掉黑"的
操作都会连印刷体一起削掉）。所以「版本B-图片」的定位是**去掉红笔批改、看清题目
原貌**，不是空白重做卷。真正能擦掉手写的是「版本B-文字」（AI 识别重排）。

改了算法后想刷新历史图片（**不重新调 AI、不花额度**）：

```bash
python3 main.py --reclean
```

## AI 答疑（流式）

AI 对话框**一直在右栏**，只有两种形态：

| 形态 | 什么时候 | 人格 | 默认模式 |
|---|---|---|---|
| **和 AI 讨论这道题** | 选中某道错题 | `TUTOR_SYSTEM` / `GUIDE_SYSTEM`，能看到题目原图 | `guide`（先问后答） |
| **问 AI 学习问题** | 没选中错题（一进首页就是这样） | `GENERAL_SYSTEM` / `GENERAL_GUIDE_SYSTEM`，全科老师，无题图 | `full`（直接讲解） |

两种形态共用**同一个消息列表模板**：对话卡放在 `<template v-if="current">` **外面**，
所以只维护一份。分成两份的话迟早会走样。

### 两条线程怎么区分：0 号位

`chats.mistake_id = 0` 就是「自由问答」线程。`mistakes` 表的 id 从 1 开始自增，
0 永远空着，拿来当哨兵值不用改表结构、不用加列，索引和动画文件命名
（`anim_m0_*.html`）全都照常工作。见 `GENERAL_CHAT_ID`（main.py）和 `GENERAL_ID`（index.html），
**两边必须一致**。

前端切线程靠 `watch: current`：`current` 变了就重载对话历史。只在「线程身份」变了时才重载
（比 id 而不是比对象），否则搜索/排序触发的列表刷新会把正在看的对话冲掉。

### 为什么自由问答默认「直接讲解」而不是「引导」

「先问后答」是为**错题复盘**设计的——有具体的卡点可点，逼孩子自己想是值得的。
但自由问答里问的多半是知识性问题（"英语作文开头怎么写"），这时候反问他没有意义，
只会让人烦。所以这里默认 `full`；想要引导，按钮里专门留了一个
**「别直接说答案，引导我想」**（`mode: guide`），让孩子自己选那条难走的路。

### 移动端

右栏在手机上是 `fixed inset-0` 的全屏层，**没选中错题时是隐藏的**——所以必须有
「问 AI 学习问题」这个入口按钮（在上传面板下面，`md:hidden`）。两个坑：

1. **返回按钮**：带「返回」的那张详情头部卡属于「选中了错题」的分支，
   自由问答态下它不存在 → 进去了就出不来。所以自由问答态另有一条自己的返回条。
2. **那条返回条必须 `sticky top-0`**：对话一进来就自动滚到底部，返回按钮要是跟着滚走，
   唯一的出口就没了。

桌面端不需要入口按钮（右栏一直在），但需要**关闭按钮**：详情头部那个 `md:order-last`
的「关闭」把 `current` 置空，右栏就回到自由问答——否则在电脑上点开一道错题之后
就再也回不到自由问答了。

其余：

- 对话**持久化**在 `chats` 表，关了浏览器下次打开还在
- 多轮上下文连续（第二轮问"有没有更快的算法"它记得第一轮在讲什么）
- 图片只挂在第一轮消息上，后续轮次纯文本，避免每轮重复消耗图片 token
- `data_uri` 为空时整条链路退化成纯文本——**绝不能**塞一个 content 为空的
  `image_url` 进去，那种消息会被 API 直接判为非法

### 防止 AI 无休止地想下去（三层保护，**按场景分档**）

这个模型的思考 token 算在 `max_tokens` 里，光设 token 上限拦不住「想很久」：
实测一次普通答疑的思考过程就有 **21092 字**，孩子盯着屏幕干等一分多钟。

但保护**不能一刀切**。我第一版图省事，给全局设了「一律 `reasoning_effort=low`、
一律 180 秒」，那是错的：生成可交互动画要规划分步、还要吐几百行 HTML/JS，
本来就该多花时间——一刀切会把动画**截断在半路**。孩子点「动画讲解」是明确
要求了「慢工出细活」，这里就该给足预算。

原则：**问答求快，创作求好**。上限仍然有，只是天花板抬高到「不可能停不下来」。

| 档位 | `reasoning_effort` | 硬时限 | 看门狗 | 用在哪 |
|---|---|---|---|---|
| `chat` | `low` | 3 分钟 | 45 秒 | 普通答疑 |
| `anim` | **不传**（用模型默认） | **10 分钟** | 90 秒 | 生成可交互动画 |

```python
AI_PROFILES = {
    "chat": {"reasoning_effort": "low", "deadline": 180, "idle": 45},
    "anim": {"reasoning_effort": "",    "deadline": 600, "idle": 90},
}
```

10 分钟不是「够用」的估计，而是「再久就一定是卡住了」的上限——真跑到 10 分钟
本身就是异常，切断并把已生成的部分保住才是对的。实测正常生成约 47 秒。

**档位由前端显式声明**（`ChatReq.want_anim`），**不做关键词猜测**：猜错了要么把动画
截断（当成问答档），要么让普通问答白等 10 分钟（当成动画档），两个方向都很糟。
前端点的是哪个按钮，它自己最清楚。

三层保护，**各管各的，谁也替代不了谁**：

| 层 | 靠什么实现 | 管的是什么 | 管不了什么 |
|---|---|---|---|
| ① 少想 | `reasoning_effort` | 从源头减少思考量 | 只是「劝」，不是保证 |
| ② 硬时限 | 循环里比对开始时间 | **总共**跑了多久（滴一个字也是跑） | 连接沉默时循环进不去，它自己也检查不了 |
| ③ 看门狗 | `httpx2` 的 **read 超时** | **多久没收到新数据**（真卡死） | 磨洋工：每次都在超时前吐一个字，它就永远不触发 |

### ⚠️ 看门狗必须做在传输层，写在循环体里是假的

第一版我把三层全写在 `for ev in stream` 的**循环体**里，实测**根本不管用**：
连接一沉默，`for ev in stream` 那一行就永远阻塞，循环体根本进不去 ——
检查和硬时限都形同虚设。实测：模拟连接卡死，它就一直干等下去，12 秒后线程还挂着。

```
第一版（超时检查写在循环里）：
  模拟「连接还在、一个字都不来」→ 12 秒后仍在阻塞 ❌ 两个机制都没生效
第二版（timeout 交给 httpx2 的 read 超时）：
  httpx2 的 read 超时是**按每次读取**算的，正好就是「多久没收到新数据就报错」
  chat 档 → read=45s    anim 档 → read=90s    实测不再阻塞 ✅
```

**教训**：凡是「在循环里检查超时」的写法，都要先问一句
「循环本身会不会卡住？」——会的话，检查永远轮不到执行。

前端还有**停止按钮**（生成中「发送」就地变成红色「停止」），模型答偏了随时能掐。

### 流式回答的中断保护（实测踩到的坑）

**原来的代码是错的。** 那段 `except GeneratorExit: 已生成的内容照样落库` 写得很好，
但**根本不会触发**：starlette 的 `StreamingResponse` 把同步生成器丢进线程池迭代，
客户端断开时只是不再消费，并不会 close 生成器。

实测确认：掐断 curl 之后，数据库一个字都没多 —— 用户等了两分钟、看到一半回答、
一刷新全没了，token 也白烧。

改法：**不再靠「结束时统一保存」，改成边生成边写**

- 一轮对话的**空壳在动手调模型之前就落库**（`_chat_begin`）。这样哪怕在思考阶段
  就关掉页面，孩子问过什么也不会丢 —— 实测过：模型光思考不吐正文时，
  掐断连接等于整轮对话凭空消失，连问题都得重打一遍。
- 正文每 2 秒 `UPDATE` 一次（`save_partial`）。SQLite 上这点写入量可以忽略。
- 每条退出路径都走一次 `finalize()`（正常结束 / 超时 / 报错 / 服务端关停），
  不留半截状态。

实测：思考阶段掐断 → 问题（20 字）+ 已生成的 631 字正文**都在**。

### 流式输出怎么做的

走 SSE（`POST /api/chat/stream`），而且**思考过程单独推流**——这是等待体验的关键：

| | 之前（整段返回） | 现在（流式） |
|---|---|---|
| 用户看到第一点反馈 | 7~30 秒后 | **0.9 秒**（思考过程开始滚） |

模型把思考写在 `delta.reasoning_content` 里（和正文分开），前端先把思考实时显示在
「💭 AI 正在思考…」区块里，正文到了再流式填进气泡，收完后思考自动收成一行摘要可再展开。

**两处必须做的合并**，否则体验反而更差：

1. **服务端合并**：模型吐的 delta 细到单字符，实测一次回答 2000+ 个片段。
   每个 SSE 事件有约 40 字节协议开销，逐字转发等于为 2KB 的回答付 80KB 网络。
   攒够 24 字或隔 60ms 才发一次 → 事件数 **2031 → 99**。
2. **前端节流**：收到的片段先攒在普通变量里，70ms 才写回响应式数据一次。
   否则 2000 次触发 Vue 重渲染，手机上会卡。
3. **渲染降级**：流式期间正文走纯文本（`whitespace-pre-wrap`），
   **收完才切到 Markdown + KaTeX 渲染** —— 否则每来一个字就重排一次公式。

> ⚠️ **成本提示**：`deepseek-flash` 默认带思考模式。实测看图答疑时**思考过程会烧掉
> 3000+ 个 token**（推理 token 按输出计费）。生成动画时更夸张——实测模型光思考就
> 烧掉约 8000 token，`CHAT_MAX_TOKENS` 才给到 32000。预算给小了会得到
> `finish_reason=length` 且正文为空，看起来像"模型不吭声"，实际是思考把配额吃光了。

## AI 生成可交互动画

AI 会输出一个自包含的 HTML 动画（抛物线逐步画出 → 标出 A、B、C → 连成三角形 →
显示面积 6 这类），**系统把它变成一个绿色按钮「打开动画 ↗」**，点一下就在浏览器里
打开，能播放、能一步步走。手机也能看。

### 必须有一个看得见的按钮（否则等于没这个功能）

**这是本应用的招牌能力，但很长一段时间里它在界面上是隐形的。** 动画原本只能被动等
模型自己想起来画 —— 没有任何地方说得出口「这题可以让 AI 画个会动的图讲给你看」。
一个用户不知道存在的功能，等于不存在。所以有两个入口：

| 入口 | 位置 | 说明 |
|---|---|---|
| **动画讲解**卡片 | 详情页，和「举一反三」并列 | 主入口：描述 + 生成按钮 + 已生成动画的画廊。默认收起，和错因/举一反三一个口径 |
| **动画讲解**常驻按钮 | 对话建议条第一位 | 快捷入口。**不参与 quickAsks/followUps 的轮换** —— 招牌功能不能被轮掉 |

生成走的是**对话链路**（`genAnim()` → `sendChat(..., 'full')`），不另开接口：
动画本来就是对话的产物，新开接口等于把整条链路重新实现一遍，还得再找一个地方存它。
动画唯一的「家」是对话消息（`anim_url`/`anim_title`），动画讲解卡只是换个视角
把它 `filter` 出来列成画廊 —— 不另存一份，两处状态就不会对不上。

两个必须注意的点：

1. **`mode` 用 `full` 而不是默认的 `guide`**。动画天生就是「把解法演示出来」，
   而引导模式明令不许给最终结果 —— 两者凑一起，模型只会左右为难。
2. **模型有时只讲不画。** 这种情况必须明说（「AI 这次只讲了思路、没画成动画」），
   否则孩子会以为是按钮坏了。判断方式就是比对生成前后 `chatAnims` 的数量。
3. **不能用 `chatSending` 驱动按钮上的「正在画…」**：那个标志对任何一条消息都为真，
   普通提问时按钮会显示成正在画动画。单独用 `animBusy`。

### 它是怎么流动的

```
模型输出  →  服务端 AnimFenceParser 拦截 HTML 围栏（不让孩子看到满屏代码）
          →  存成 static/anim/anim_m<错题id>_<时间戳>.html
          →  推一个 SSE 事件 {"type":"anim","title":...,"url":...}
          →  前端渲染成按钮 + 可选的页内预览
```

### 踩过的三个坑

**1. 围栏可能被切成任意碎片。** 标题长度不定，所以不能「扣留前 N 个字符」——
早期版本只扣 11 字符（关键词长度），标题还没到齐缓冲区就被放行，代码直接漏到界面上
（逐字符喂入时 100% 复现）。改成三状态机 `text → header → anim`。
自测要求：**把整段围栏逐字符喂进去，结果必须和一次性喂入完全一致**。

**2. 模型不会乖乖用你指定的围栏。** 提示词里写 ```html-anim，它仍然会退回最顺手的
```html。与其跟模型的先验较劲，不如三种都认。

**3. 模型有极强的「教你手工保存文件」先验。** 实测提示词里连写「禁止」也压不住，
它坚持输出「新建文本文档 → 粘贴代码 → 保存为 .html → 双击打开」，甚至推荐用
LICEcap 录屏。所以除了提示词（改成正面说法「按钮已经存在」+ 给样例），还加了
**代码级兜底** `ManualStepFilter`：按行丢弃这类句子。它只扣「当前没写完的那一行」，
扣留上限 200 字符，所以不会毁掉流式手感。

### 安全：动画页是沙箱化的

动画 HTML 里含模型生成的 JS，**会在浏览器里执行**。如果按普通同源页面提供，它就能
带着用户的登录态去读写 `/api/*`——而它的输入里包含用户上传的试卷图片，存在提示注入
的可能。所以 `/anim/xxx` 响应带这样的头：

```
Content-Security-Policy: sandbox allow-scripts; default-src 'none';
  script-src 'unsafe-inline' https://cdn.jsdelivr.net; ...  connect-src 'none'
```

关键点：**sandbox 故意不给 `allow-same-origin`** → 动画页被降级成不透明源，读不到
Cookie/localStorage，发出的同源请求带不上登录态也读不到响应；`connect-src 'none'`
再掐断一切外部请求，杜绝把数据外传。

文件名还要过白名单正则 `^anim_m\d+_\d+\.html$`（路径穿越测试全 404）。
清空某题的对话记录时，它生成的动画文件会一并删除。

> 另外注意：**生成动画很慢**（实测 18~85 秒，取决于模型思考多久）。流式输出会一直
> 显示思考进度，不是卡死。

## 对话区的内容渲染

AI 的回答会经过一条**五步管线**（`index.html` 里的 `mdToHtml`），顺序不能乱：

```
① 给「裸公式」补分隔符  →  ② 把已有公式整段藏起来  →  ③ 跑 Markdown
                        →  ④ 还原公式  →  ⑤ 交给 KaTeX 渲染
```

每一步都是踩坑踩出来的：

**① 模型经常不写 `$`。** 实测它会直接吐 `I=\frac{U}{R}=0.2\text{A}` 这种裸公式，
而 KaTeX 只认分隔符 —— 孩子看到的就是一堆 `\frac{}{}` 源码。所以要自动补。
判断规则：一段连续字符里含 LaTeX 命令（`\frac` `\text` `\Omega` …）就包成公式；
独立成行的用 `$$`（块级居中），嵌在句子里的用 `$`（行内）。

**② 不藏起来的话 Markdown 会吃掉公式。** 实测 `$a*b*c$` 会变成 `$a<em>b</em>c$`，
`\begin{aligned}` 里的 `\\` 和 `&` 被改写成 `<br>` 和 `&amp;`。

**③ 模型不只用 `$`。** 它还常用 `\(...\)` 和 `\[...\]` 这套写法，都是合法的。
早期版本只判断 `$`，于是把 `\(U=6\text{V}\)` 又包了一层，产出
`$\(U=6\text{V}\)$` 这种坏结构 —— 所以「藏起来」那步必须认全四种分隔符。

**④ 化学式也要认。** `Na_2CO_3` / `Ca(OH)_2` 没有 LaTeX 命令，但下划线原样显示很难看。
用一条专门的正则识别，**要求整串里必须有数字** —— 这条约束是挡住 `NASA` / `OK` / `A4`
不被误包的关键（代价是纯字母的 `NaOH` 不会被包，但它本来就没有下划线，原样显示也没问题）。

**⑤ 行首的 Markdown 标记要留住。** `- I=\frac{U}{R}` 里的 `- ` 如果被一起包进公式，
列表结构就没了，公式里还会多一个减号。

**还有个坑在服务端**：给模型的系统提示词 `TUTOR_SYSTEM` 必须写成 `r"""..."""`。
普通字符串里 `\b` `\f` 会被 Python 当成退格/换页符吃掉，`\\begin{aligned}` 会变成
`egin{aligned}`、`\frac` 变成 `rac` —— 等于把坏掉的格式示范喂给模型，它当然照着学。

## 默认「先问后答」：AI 是脚手架，不是拐杖

教育研究里有个说法：AI 用得对不对，不取决于技术，取决于**人机互动的模式**。
直接拍照出答案会产生"虚假精通"——看的时候觉得懂了，考试还是不会。
所以这个 app 的 AI 答疑**默认是引导模式**：

| 模式 | AI 的行为 | 什么时候用 |
|---|---|---|
| `guide`（默认） | **绝不输出完整过程、绝不给最终答案**；先反问「你打算从哪下手」，一次只给**一层**提示 | 平时 |
| `full` | 完整规范解答 | 孩子点「我实在想不出来」之后 |

界面上，「我实在想不出来」那个按钮**单独用琥珀色标出来**，跟其它建议按钮区分开——
让它看起来就不像一条"捷径"，孩子要多想一下才会点。

实测效果（物理串联电路那题，引导模式）：

> 先别急着让我讲——你看你卷子上那三行，步骤完整、单位齐全，老师红笔打了个大勾，
> 说明**你当时是会做的**。所以咱们换个玩法：**你当老师，我当学生**，你把它讲给我听。
> 我先把电路图给你重画清楚一点，你对着图讲。

它读了原图、发现孩子其实做对了、拒绝直接讲、还把角色反转过来——**4 个反问、0 个答案**。

### 使用频率提示

顶部常驻「本周问 AI N 次」。超过 6 次会变琥珀色并附一句「试着先自己想一想」。
（报告：每周 1~2 次使用的学生成绩最好，每天高频使用的反而落后。）

每轮提问的模式都会记进 `chats.mode`，以后要给孩子/家长出一份"求助方式报告"就有数据了。

## 两种题型：错题 + 经典题

上传的不一定是错题——**经典好题、压轴题、值得反复琢磨的题**也一起管理。
两类题共用一个列表、一张详情页、一套对话，差别只有三处：

| | 错题 `mistake` | 经典题 `classic` |
|---|---|---|
| 判据 | 照片上**有做错的痕迹**（手写算错、叉、扣分、订正） | 照片上**没有做错的痕迹**（空白题、做对、老师发的例卷） |
| `analysis` 装什么 | 错因分析：错在哪一步、为什么会这么错 | 好在哪：妙在哪、关键一步、这类题的通法 |
| 分析卡标题 | 这道题错在哪 | 这道题好在哪里 |

**判据只有「有没有做错的痕迹」这一条**，跟题目难不难无关——实测一道三问的二次函数
压轴题（面积最值 + 平行四边形存在性）也正确判成了 `classic`，因为卷面干净、没有作答痕迹。
提示词里专门写了这句，否则模型很容易把「难」当成「经典」。

**AI 自动判，判错了手改**：跟科目同一套逻辑——与其让用户上传前先选，不如先认、
认错了再改。详情页那个题型下拉走 `PATCH /api/mistakes/{id}`，改完分析卡标题和
举一反三的提示语会跟着换口径。

字段设计上有两个注意点：

1. **列名从 `error_analysis` 改成了 `analysis`**。经典题存进去的是一段「妙在哪」，
   列名不改的话，以后读到 `error_analysis` 里是表扬会当场懵住。迁移走
   `ALTER TABLE ... RENAME COLUMN`（SQLite ≥ 3.25），只在老库上跑一次，已逐行比对确认不丢数据。
2. **AI 的系统提示是围绕「复盘错题」写的**，开头那句「先点破卡点」对经典题完全不适用。
   解决办法不是复制一整套提示（两份迟早各自漂移），而是在 `build_question_context()`
   末尾追加一段**显式声明优先级**的覆盖说明——照片上没有错误过程，硬找错因就是编造。

列表上方有 `全部题型 / 错题 / 经典题` 三个筛选按钮（带计数），导出弹窗的
「当前筛选」也跟着走，筛出经典题再导出不会混进错题。

### 顺手修掉的一个老 bug

`JSON_HINT` 在 main.py 里被定义了**两次**（一次给上传提取、一次给变式题），
Python 取后一个 → 上传提取那条链路实际拿到的是变式题的 hint，跟 `SYSTEM_PROMPT`
自相矛盾。删掉了没人用的那一个。

## 错因分析才是主体，举一反三按需生成

上传时 AI 提取四个字段：`kind`（题型）、`tag`（考点）、**`analysis`（分析）**、`clean_text`（纯净题干）。

**为什么把「错因分析」放主体**：错题本的核心价值是**弄明白这道题错在哪、为什么会这么错**，
而不是马上再做一道新题。变式题（举一反三）是下一步的事，占着主界面反而喧宾夺主。

AI 看得到学生的**手写过程**和老师的**红笔批改**，所以能指到具体那一行：
「你第(1)问写 $y=(x-1)^2+4$，顶点写成 $(1,4)$ —— 配方时漏掉了常数抵消」。
它还要求**不写完整解答**（只给方向），并在照片看不出错因时**如实说看不出，绝不硬编**。

**举一反三改成按需**：上传时不再生成（省 token、也不占注意力），界面上是一个收起的
折叠卡片，点「生成变式题」才调 `POST /api/variant/{id}`。生成时会把**错因**一并喂给模型，
要求新题重点针对同一个坑：

> 实测生成的变式题解析里直接写：「关键卡点：括号内加了 9，括号外必须减 9，
> 再与原来的 +5 合并，得 $-9+5=-4$，**不能漏掉常数抵消，更不能写成 $(x+3)^2+4$**」

而那正是学生在原题上犯的错。第二次点击走缓存（0.008 秒返回），不重复花钱。

## AI 画图（内联 SVG + 可交互动画）

模型不能直接产出**位图文件**，但它可以用代码画图。这个项目做了两条路：

| 需求 | 走哪条 | 呈现 |
|---|---|---|
| 静态示意图（几何图形、受力分析、电路、光路、函数图像） | ` ```svg ` 围栏 | **直接画在回答里** |
| 要播放/拖动/分步演示的 | ` ```html-anim ` 围栏 | 绿色按钮「打开动画 ↗」+ 页内预览 |

### 内联 SVG 的安全处理（重点）

模型生成的 SVG 要**注入进聊天页的 DOM**，这是个 XSS 面：它的输入里包含用户上传的
试卷图片，存在提示注入的可能。所以：

1. 走 **DOMPurify** 的 svg 配置过滤（`USE_PROFILES: {svg, svgFilters}`），
   并显式禁掉 `<script>` `<style>` `<foreignObject>` `<animate>`。
2. **拿不到净化器就绝不注入**——宁可把源码显示出来，也不把未过滤的 SVG 塞进页面。
3. 实测拦住了：内联 script、`onload=`、`foreignObject` 偷 HTML、`javascript:` 链接、
   `<style>` 注入、`<animate>` 改 href。

> 注意这跟 `/anim/xxx`（动画页）是两套隔离：动画页跑在 **CSP sandbox 的不透明源**里，
> 内联 SVG 则是净化后进主文档——因为它要跟文字混排，不能开 iframe。

### 画图规范（写给模型的）

`TUTOR_SYSTEM` 里给了**一个完整的串联电路 SVG 范例**，并强调：

- 必写 `viewBox`，不写死 width/height（手机也要好看）
- 线条文字用 `currentColor`（深浅背景都可读），只给关键元素一个强调色
- 箭头用 `<defs><marker>`，不用图片
- 图上必须有标注（顶点、边长、力的大小方向、元件数值）
- **禁止 ASCII 字符拼图**（`┌──S──[R1]──┐`）——那种图手机错位、没法缩放

> 实测教训：只写「禁止 ASCII 图」没用，模型照样画。**换成给一个真实 SVG 范例之后
> 立刻就画对了**。跟之前围栏格式的问题是同一个规律——样例比禁令有效得多。
>
> 范例本身也用 `cairosvg` 渲染验证过（渲染器缺中文字体时中文会变方块，
> 那是本机字体问题，浏览器里正常）。

## 滚动结构（为什么是两条）

桌面端是应用壳：`#app` 锁死 `h-screen + overflow-hidden`，页面本身**永不滚动**；
左栏（错题列表）和右栏（题目详情）**各自**是滚动面板，各一条滚动条。

为什么不是"只有一条"：列表要随时能切题、详情又比屏幕高，这两件事放在一个屏幕里，
结构上就必然要两个独立滚动区。这条曾被反复质疑，所以用无头浏览器实测过
（见 `~/.claude/projects/*/memory/headless-browser-installed.md`）：
**16 种窗口尺寸 × 全部错题 × 一次完整 AI 对话，滚动容器恒为 2，页面零溢出。**

### 踩过的坑：嵌套滚动容器

`overflow-y-auto` 会给**任何**内容超高的元素加一条滚动条，包括你没意识到的地方。
实测抓到过两个：

1. 聊天里的「思考过程」盒子（`max-h-44 overflow-y-auto`）——思考内容动辄 3000+ 字，
   它自带的滚动条就贴在右栏滚动条旁边，屏幕上同时出现 **3 条**。
   修法：流式期间只显示思考内容的**尾部**（最后 320 字，正好是"现在在想什么"），
   收完展开显示全文、随页面滚，全程不再有内部滚动条。
2. AI 输出的代码块/长公式/宽表格默认不换行，会在面板里撑出**横向**滚动条。
   修法：`.rich pre/code/table` 强制换行自适应。

> 教训：`overflow` 造成的嵌套滚动**看不出来，只能量**。改布局后务必跑一次
> 「筛出所有 `overflow-y` 是 auto/scroll 且 `scrollHeight > clientHeight` 的元素」。

### 流式思考框为什么要固定高度（屏幕上下抖动）

原来思考框是**按内容自适应高度**的：流式期间显示「最后 320 个字符」——
字数固定，但**换行行数不固定**（中文在哪儿折行每次都不一样），
盒子高度就在 3~10 行之间来回跳。

实测采样（每 60ms 一次）：

```
修复前：思考框高度 67→106→164→203→164→…→184→125→106px，12/70 次采样在变
        内容总高 2213→2252→2311→2350→2311→2252   ← 涨上去又缩回来
        滚动位置：向下 19 次、向上 3 次            ← 上下反复 = 抖动
修复后：思考框高度恒为 126px，0/19 次变化；滚动只向下，0 次向上
```

内容高度一上一下地动，而自动滚动又钉着底部，表现就是**整个屏幕不停上下抖动**。
改法：流式期间给思考框一个**固定高度**（`h-[96px]`）+ `overflow-hidden` +
**底部对齐**（`flex items-end`）。高度恒定不动，超出的部分从上方裁掉，
孩子始终看到的是「现在在想什么」。

### 输入框怎么钉在底部（不要用 sticky）

一开始用的是 `position: sticky; bottom: 0`，**实测无效**：sticky 只能在**包含块范围内**
上移，而输入框位于详情最底部、包含块只有两百多像素高，最多挪一小段就卡住了
（滚到顶部时它跑到 y=1032，而可视区底部只有 884）。

正确做法是**换布局**——右栏做成 flex 列，输入区根本不在滚动容器里：

```
右栏 section  flex flex-col
 ├ 滚动内容区   flex-1 min-h-0 overflow-y-auto   ← 所有卡片 + 聊天消息
 └ 固定底栏     shrink-0                          ← 建议按钮 + 输入框，天生不滚
```

实测（滚到顶 / 中间 / 最底三种状态）：输入框坐标**全程不变**，且「底栏在滚动容器内 = 否」。

> 排查这类问题**必须量，不能读代码猜**。而且量的时候要跟**视口**比，不是跟父容器比——
> 我第一版测试就是拿输入框和右栏比，两者都超出屏幕，于是得出了假的"✅"。

### 页面本身为什么不用 `100vh`

桌面端原本用 Tailwind 的 `h-screen`（= `100vh`）。`vh` 有几个已知坑：浏览器缩放
不是 100% 时 `100vh` 会比可视区高 1px；传统滚动条占位与 `vh` 取整相互作用也可能
多出滚动条。现在改成 `html → body → #app` 逐级 `height: 100%`，再加
`html, body { overflow: hidden }`，页面滚动条从根上不可能出现。

> ⚠️ **自动化测试的盲区**：headless Chromium 用的是**悬浮滚动条（占 0px）**，
> 真实浏览器（Windows/Linux）多是**传统滚动条（占 ~15px）**。所以有些滚动条问题
> 在自动化测试里**根本复现不出来**。核对真实环境请用下面的自检面板。

### 布局自检面板

浏览器打开 `http://<地址>:8000/#debug`，会直接列出：

- 视口尺寸、DPR、**滚动条占宽**（0 = 悬浮式还是传统式）
- 页面本身的纵向/横向溢出量
- **所有真的会产生滚动条的元素**及其位置、尺寸、内容高度

排查「屏幕上到底有几条滚动条」只用这一个面板，比读代码猜可靠得多。

## 站点图标

标签页、收藏夹、手机「添加到主屏幕」用的图标，和页面顶栏 `<use href="#i-book"/>`
是同一枚：靛蓝渐变圆角方块 + 白色线描书。同一份路径数据出现在三处，改的时候要一起改：

| 位置 | 用途 |
|---|---|
| `static/favicon.svg` | 主图标（矢量，任意分辨率都清晰） |
| `static/favicon.ico` | 内含 16/32/48 三档，给不认 SVG 的老浏览器 |
| `static/favicon-192.png` | PNG 兜底 |
| `static/apple-touch-icon.png` | 180×180 **满幅不透明、不带圆角**——圆角由 iOS 自己套，
预先做圆角会被二次裁切导致边缘发虚 |
| `index.html` 的 `<symbol id="i-book">` | 页面顶栏图标（`currentColor`，跟随文字色） |
| `LOGIN_PAGE` 的 `.logo` 内联 `<svg>` | 登录页大图标，与上面同源同形 |

图标走**独立静态路由**而不是 `data:` URI：能 HTTP 缓存，且 iOS 的
`apple-touch-icon` 只认真实 URL。

**坑（必读）**：图标路径必须加进 `PUBLIC_PATHS`。浏览器请求 favicon 时不带任何
上下文也不带登录态，一旦被 `auth_guard` 302 到 `/login`，浏览器会把登录页的 HTML
当图片解析 —— 结果是**标签页图标空白，而且控制台不报错**，很难联想到是登录拦截。
`/apple-touch-icon-precomposed.png` 也一并放行：iOS 会先探这个名字，缺了就多一次
404 往返（路径映射到同一份 PNG）。

重新生成图标（`cairosvg` + `Pillow`）：

```bash
python3 - <<'PY'
import cairosvg, io
from PIL import Image
BOOK = ('<g fill="none" stroke="#ffffff" stroke-width="1.95" stroke-linecap="round" '
        'stroke-linejoin="round" transform="translate(2.6667 2.6667) scale(1.1111)">'
        '<path d="M4 19V5.5A2.5 2.5 0 0 1 6.5 3H19a1 1 0 0 1 1 1v16a1 1 0 0 1-1 1H6.5a1 1 0 0 1 0-2H20"/>'
        '<path d="M8 7h7"/></g>')
GRAD = ('<defs><linearGradient id="g" x1="0" y1="0" x2="1" y2="1">'
        '<stop offset="0" stop-color="#4f46e5"/><stop offset="1" stop-color="#7c3aed"/>'
        '</linearGradient></defs>')
svg = lambda rx: (f'<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 32 32">'
                  f'{GRAD}<rect width="32" height="32" rx="{rx}" fill="url(#g)"/>{BOOK}</svg>')
png = lambda rx, n: Image.open(io.BytesIO(cairosvg.svg2png(
    bytestring=svg(rx).encode(), output_width=n, output_height=n))).convert("RGBA")
touch = Image.new("RGBA", (180, 180), (79, 70, 229, 255))
touch.alpha_composite(png(0, 180)); touch.convert("RGB").save("static/apple-touch-icon.png")
png(7.2, 64).save("static/favicon.ico", format="ICO", sizes=[(16,16),(32,32),(48,48)])
png(7.2, 192).save("static/favicon-192.png")
PY
```

深色标签栏下这个图标同样清晰（底色是饱和靛蓝，不依赖透明背景）。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/upload` | multipart：`file` + `subject`，跑完整双轨处理 |
| GET | `/api/mistakes` | 参数：`subject` / `q`（搜索）/ `order` |
| DELETE | `/api/mistakes/{id}` | 删除（连带删图） |
| GET | `/api/stats` | 各科目错题数量 |
| POST | `/api/export_pdf` | 见「导出打印」的维度，返回 A4 PDF |
| PATCH | `/api/mistakes/{id}` | 改归档科目 |
| POST | `/api/variant/{id}` | **按需**生成同考点变式题（已有则直接返回，不重复花钱） |
| GET/POST/DELETE | `/api/chat` | AI 答疑：`GET /api/chat/{id}` 取历史，`POST` 提问 |
| POST | `/api/login` `/api/logout` | 登录 / 登出 |
| GET | `/api/health` | 健康检查 + `ai_ready` |

### 科目：AI 自动识别，认错了再改

上传时**不需要用户选科目**——AI 从图上认出考点（标签形如「语文-记叙文写作」），
后端取标签前缀作为归档科目。响应里用 `subject_fixed_from` 告知前端「你选的 X 被纠正成 Y」。

认错了怎么办：详情页的科目标签**本身就是个下拉**，点一下就能改，
走 `PATCH /api/mistakes/{id}`。

### 筛选按钮上的计数必须跟着筛选走

题型按钮（全部题型 / 错题 / 经典题）上的数字曾经读的是**全库**的 `by_kind`，
于是筛了「语文」之后，按钮上还挂着全库的 12 / 5，而列表里只有 1 道 ——
**看起来就像筛选根本没生效**。数字是筛选是否生效最直接的反馈，这里错不得。

`/api/stats` 现在多返回一个 `by_subject_kind` 交叉计数，前端按当前科目取。
顺带把导出弹窗的「当前筛选」计数从「最多 N 道」的上界改成了准确值
（以前算不出来，只能在界面上标「最多」二字遮丑）。

> 这里踩过一个设计矛盾：最初让用户上传前手选科目，结果顶部筛选在「全部」时
> 会**静默默认成数学**，把语文卷归到数学去。我当时的补法是「后端用 AI 纠正」+ 前端
> 弹提示——但那等于**把 AI 已经做的事又推回给人做一遍**。
> 正确的做法就是现在这样：默认全自动，只保留事后修正的入口。

## 常见问题

**手机打不开 `http://<IP>:8000`？**

公网服务器（阿里云 ECS）：
1. **九成是这个原因**：安全组没放行 8000 —— 见上面「开放公网访问」
2. 确认服务在跑且监听 `0.0.0.0`：`ss -tlnp | grep 8000`
3. 本机自测绕过安全组：`curl -I localhost:8000` （返回 302 就说明服务正常，问题在网络层）

家里电脑：
1. 确认手机和电脑在同一个 WiFi（不是手机流量）
2. 防火墙放行 8000：`sudo ufw allow 8000`

**忘记口令了？**
`cat password.txt` 即可。想换一个：改这个文件后重启，或 `export APP_PASSWORD=新口令`。

**PDF 里中文是空白？**
程序会自动下载 Noto Sans SC 到 `./fonts/` 并把字形嵌进 PDF（首次约 17MB）。
若下载失败且系统又没有任何中文字体，会退回 reportlab 内置的 `STSong-Light`，
而它是 **Adobe CID 字体、不嵌入字形**，Chrome/pypdfium2 等常见阅读器会显示空白。
手动修复：装一个中文字体即可，例如 `sudo apt install -y fonts-wqy-microhei`。

**手机拍照需要 HTTPS 吗？**
不需要。这里用的是 `<input type="file" capture="environment">`（调系统相机），
不是 `getUserMedia`，所以在普通 HTTP 局域网下也能正常调起相机。

**上传很慢？**
前端会先把照片压到 2000px，实际只传 1~2MB。真正耗时的是服务端 AI 解析（约 10~30 秒）。
